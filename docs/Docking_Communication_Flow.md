# 桶体与基站串口对接流程

## 1. 串口和接线

| 设备 | 串口 | TX | RX | 参数 |
|---|---|---|---|---|
| 桶体 | USART2 | PA2 / MCU_TX | PA3 / MCU_RX（内部上拉） | 9600, 8N1, 无流控 |
| 基站 | USART3 | PB10 / LOG_RX1 | PB11 / LOG_TX1（内部上拉） | 9600, 8N1, 无流控 |

接线必须交叉：桶体 TX 接基站 RX，桶体 RX 接基站 TX，并连接公共 GND。内部上拉只用于稳定空闲或断线时的 RX 电平，不能替代良好的地线、屏蔽或差分收发器。

30 字节协议帧在 9600 baud、8N1 下约需 31.25 ms。当前 1 s 心跳/状态周期足够；如后续连续命令造成排队，可将两端同时提高到 19200，再视情况提高到 38400，禁止只改一端。

## 2. 对接前

桶体上电后把基站在线状态置 0，关闭排水授权和充电，并设置 `B1WAIT=1`。Linux 主控也必须先发送合法帧，桶体才把 Linux 判为在线。

基站上电后把桶体在线状态置 0，执行器保持安全停止。若 5 s 内没有收到桶体合法帧，继续保持离线并执行掉线停机保护。

## 3. 对接中（安全握手）

1. 接好 TX/RX/GND 和对接电源后，桶体检测 DCIN 是否高于 13.0 V。
2. 只有 Linux 在线且 DCIN 有效时，桶体才通过 USART2 发起基站链路。由于上电或掉线后 `B1WAIT=1`，首先发送特殊安全帧：命令 `B1`，并令 `frame[28]=0xA5`。
3. 基站 USART3 收到帧头、长度和校验都正确的帧后，刷新桶体在线计时，将自身的桶体连接状态置 1。识别到特殊 B1 后，立即停止基站输出、清除旧动作并进入待机。
4. 基站立即回复状态帧；其中 `frame[3]=B1`、`frame[4]=1`、`frame[23]=0x03`（待机）。基站也会约每秒主动回复状态。
5. 桶体收到模式为 `0x02` 的合法基站帧后，更新接收时间。只有确认 `B1 + 待机状态 0x03` 后才清除 `B1WAIT`。
6. 桶体最终判定基站在线必须同时满足：DCIN > 13.0 V、3 s 内收到合法基站帧、基站返回 `frame[4] != 0`，并且安全 B1 已确认。

这样可以识别 TX 或 RX 单边断线：只收到基站数据但基站没收到桶体数据时，基站返回的 `frame[4]` 为 0，桶体不会上报在线。

## 4. 对接后

桶体约每秒向基站发送心跳或 Linux 的透传业务帧，基站收到后立即应答，并约每秒发送状态帧。桶体把最终基站在线结果写入发给 Linux 的状态帧 `frame[4]`。

排水只有 Linux 在线和基站双向在线时才被授权。充电同样要求 Linux 与基站都在线；电池低于启动阈值并持续满足延时后才开启，任一链路掉线立即关闭。

## 5. 掉线与重新对接

- 桶体超过 3 s 没收到合法基站帧、DCIN 失效、或基站返回 `frame[4]=0`：立即撤销排水授权，停止桶体输出和充电，并重新置 `B1WAIT=1`。
- Linux 超过 5 s 无合法帧：桶体停止所有输出和充电、撤销排水授权，并停止普通基站心跳；基站随后由自己的超时保护停机。
- 基站超过 5 s 没收到桶体合法帧：把桶体连接状态置 0，并立即停止基站全部输出。
- 重新接通后，桶体不会直接恢复旧命令，而是再次发送安全 B1。只有收到基站已待机的确认后才重新上报在线；旧排水、加热、注水或清洁动作不会续跑，必须由 Linux 下发新命令。

## 6. `[DOCK]` 日志判读

桶体日志格式：

```text
[DOCK] ON:1 DC:24.5V PWR:1 LNX:1 LA:120ms RX:35 RA:80ms VA:80ms ACK:1 B1WAIT:0 LAST:02/B1/01/03
```

| 字段 | 含义 | 正常对接期望 |
|---|---|---|
| `ON` | 桶体最终判定的基站在线状态 | 1 |
| `DC` / `PWR` | 对接电压 / 是否超过 13.0 V | 电压正常 / 1 |
| `LNX` / `LA` | Linux 在线 / 最近合法 Linux 帧时间 | 1 / 小于 5000 ms |
| `RX` / `RA` | 收到并通过校验的基站帧数 / 最近帧时间 | 持续增加 / 约小于 1000 ms |
| `VA` | 最近模式为 0x02 的有效基站帧时间 | 约小于 1000 ms |
| `ACK` | 基站 `frame[4]`，确认其收到桶体帧 | 1 |
| `B1WAIT` | 是否仍等待安全待机确认 | 正常联网后为 0 |
| `LAST` | 最近帧的 mode/cmd/ack/status | 握手可见 `02/B1/01/03` |

快速定位：`RX` 不增加先查基站 TX→桶体 RX；`RX` 增加但 `ACK=0`，查桶体 TX→基站 RX；`PWR=0` 查 DCIN；`LNX=0` 查 Linux 链路；`B1WAIT=1` 且 RX/ACK 正常，检查基站是否确实回复 B1 且状态为 0x03。
