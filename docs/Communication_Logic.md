# 主控端、桶体端、基站端通信逻辑说明

本文基于当前代码整理通信行为。

## 1. 串口角色与周期

| 端口 | 对端 | 用途 | 初始化波特率 |
|---|---|---|---|
| USART1 | Linux 主控端 | 接收主控命令、向主控上报桶体状态 | `UART_Comm_Init()` 中强制为 115200 |
| USART2 | 基站端 | 中转模式下与基站互传帧 | `UART_Comm_Init()` 中强制为 9600，RX 内部上拉 |
| USART3 | 调试日志口 | 只输出日志，不参与协议帧通信 | 115200 |

相关周期：

| 项目 | 当前值 | 代码含义 |
|---|---:|---|
| 通信任务周期 | 50 ms | `Communication_Task` 每 50 ms 调用 `UART_Comm_TaskProcess()` |
| 桶体状态主动上报周期 | 1000 ms | 每秒向 Linux 主控端发送一帧状态 |
| 主控通信超时判断 | 5000 ms | 超过 5 s 未收到 Linux 合法帧，桶体持续关闭输出与充电、清定时，并向基站发送安全停机帧 |
| 桶体兜底基站心跳 | 1000 ms | Linux 在线且最近没有向基站发送数据时，桶体主动发送一帧 `0x02/0x00` 实时数据 |
| 基站连接超时判断 | 3000 ms | DCIN 有效、3 s 内收到合法帧、`frame[4]=1` 且重连安全停机已确认才认为在线 |
| 日志打印周期 | 1000 ms | USART3 输出文本日志 |

## 2. 协议帧格式

所有协议帧固定 30 字节：

| 字节 | 含义 |
|---:|---|
| `frame[0]` | 帧头 1，固定 `0x55` |
| `frame[1]` | 帧头 2，固定 `0xAA` |
| `frame[2]` | 链路模式 |
| `frame[3]` | 命令字 |
| `frame[4]..frame[28]` | 数据区 |
| `frame[29]` | 校验和 |

校验规则：

```text
checksum = (frame[2] + frame[3] + ... + frame[28]) & 0xFF
frame[29] 必须等于 checksum
```

链路模式 `frame[2]`：

| 值 | 名称 | 当前逻辑 |
|---:|---|---|
| `0x01` | 桶体模式 | 主控命令由桶体端执行 |
| `0x02` | 中转模式 | Linux 发来的合法帧都会转发给基站；A 段命令和 `0xB4` 同时由桶体本地解析；基站数据会合并到桶体状态帧后上报主控 |
| `0x03` | 直连模式 | 认为是合法模式，但当前没有额外直连转发逻辑 |

非法链路模式的 Linux 帧会被丢弃。

## 3. 接收与发送机制

接收：

- USART1 和 USART2 都使用 `HAL_UARTEx_ReceiveToIdle_DMA()`。
- DMA 接收缓冲区长度为 128 字节，循环模式。
- 每次串口 idle/rx event 回调后，代码把新增字节喂给帧解析器。
- 解析器按 `0x55 0xAA` 帧头同步，累计满 30 字节后校验；校验通过才放入待处理槽。

发送：

- USART1 和 USART2 都有独立发送槽。
- 如果当前串口空闲，立即 DMA 发送。
- 如果正在发送，新帧写入 `pending_frame`，等待当前帧发送完成后再发。
- 同一串口忙时多次写入会覆盖 pending，只保留最新一帧。

中断回调：

- `HAL_UARTEx_RxEventCallback()` 调 `UART_Comm_RxEventCallback()`。
- `HAL_UART_TxCpltCallback()` 同时通知协议发送和日志发送。
- `HAL_UART_ErrorCallback()` 会重启 USART1/USART2 接收；USART3 错误由日志模块恢复。

## 4. Linux 主控端到桶体端

Linux 主控端通过 USART1 发送 30 字节协议帧。

处理顺序：

1. 帧头、长度、校验通过后进入 Linux 接收槽。
2. 通信任务取出该帧。
3. 检查 `frame[2]` 是否为合法链路模式。
4. 记录主控通信时间：
   - `last_link_mode = frame[2]`
   - `main_last_rx_tick = HAL_GetTick()`
   - `main_frame_received = 1`
   - `main_timeout_handled = 0`
5. 根据 `frame[3]` 执行命令。
6. 若命令被桶体端处理，立即向 USART1 回一帧状态。

主控通信连接状态：

- 代码每 50 ms 检查一次是否超过 5 s 未收到 Linux 合法帧。
- 超时后持续关闭桶体全部输出和充电、清除定时/自检、撤销排水授权并进入待机；收到下一帧合法 Linux 数据后才解除超时状态。
- 上报帧里没有单独的“主控是否在线”字段。

## 5. 桶体端执行的主控命令

命令字 `frame[3]`：

| 命令 | 值 | 桶体端行为 | 是否立即回状态 |
|---|---:|---|---|
| 空闲 | `0x00` | 只记录命令 | 是 |
| 关闭 | `0xA0` | 停止所有输出，清定时，主状态设为关闭 | 是 |
| 待机 | `0xA1` | 停止所有输出，清定时，主状态设为待机 | 是 |
| 开加热 | `0xA2` | 设置目标温度 `frame[6]`，开启加热，水泵循环，运行状态 | 是 |
| 关加热 | `0xA3` | 关闭加热；若 UV 未开则关水泵；运行状态 | 是 |
| 电机 | `0xA4` | 电机档位取 `frame[7]`；档位 0 为待机，否则运行 | 是 |
| UV | `0xA5` | UV 状态取 `frame[8]`；开 UV 时开水泵循环；关 UV 且未加热时关水泵 | 是 |
| 定时 | `0xA6` | 定时编码取 `frame[9]`，同时同步温度/电机/UV/水泵状态 | 是 |
| 停止 | `0xA7` | 停止所有输出，清定时，待机 | 是 |
| 自检 | `0xA8` | 停止所有外设、清故障并立即上报自检状态 `0x01`；保持 5 s，期间周期帧维持 `0x01`；完成后设为开机 `0x00` 并再次上报 | 是 |
| 低功耗 | `0xA9` | 停止所有输出，主状态设为低功耗 | 是 |
| 调试水泵阀 | `0xB4` | 仅当 Linux 与基站均在线时打开水泵+排水阀，否则泵阀底层拒绝排水 | 是 |
| 系统复位 | `0xC0` | 停止所有输出，请求 200 ms 后复位 | 是 |

自检保持期间，桶体会忽略其它 A 段控制命令，防止外设被重新开启；这些命令仍会触发状态回包，但 `frame[12]` 保持为 `0x01`。重复发送 `0xA8` 会重新开始 5 s 自检计时。

自动上水 `0xB2` 的目标水位取基站数据区 `frame[16]`；`frame[5]` 属于桶体数据区，只表示桶体当前水位。桶体收到 `0xB2` 后先主动发送一帧带当前 `frame[5]` 水位、`frame[6]` 温度和内部令牌的 `0x00` 实时快照；只有基站回显本次令牌后才转发 B2。自动上水过程中仍由主控周期 `0x00` 空闲命令持续更新实时水位和温度。

定时编码 `frame[9]`：

| 编码 | 定时时长 |
|---:|---:|
| `1` | 10 分钟 |
| `2` | 15 分钟 |
| `3` | 20 分钟 |
| `4` | 25 分钟 |
| `5` | 30 分钟 |
| 其它 | 清除定时 |

## 6. 主控端到基站端转发

只要满足以下条件，Linux 帧就会从 USART1 转发到 USART2：

```text
frame[2] == 0x02       // 中转模式
```

转发行为：

- 除空闲命令 `0x00` 和采用有序握手的自动上水 `0xB2` 外，其它主控原始30字节帧不改内容，直接发给基站端。
- 空闲命令 `0x00` 会复制主控原帧，只用桶体当前水位刷新 `frame[5]`、当前温度刷新 `frame[6]`，再重新计算 `frame[29]` 校验和后发给基站端。
- 自动上水 `0xB2` 保留目标水位 `frame[16]`、目标温度 `frame[6]` 等业务参数，但在 Bucket→Base 内部链路使用令牌字段区分前置实时帧与 B2 结果并重新计算校验和；`0xA2`、`0xA6` 等其它命令仍原样转发。令牌不进入 Linux 状态帧，不是新增产品协议字段。
- 转发后，桶体端仍继续判断是否需要本地解析。
- A 段命令、空闲命令 `0x00` 和 `0xB4` 调试命令会在桶体本地执行，并立即回一帧桶体状态给 Linux。
- 其它中转命令只转发给基站，不触发桶体状态立即回包；桶体仍会按 1 秒周期主动上报状态。

注意：

- `frame[2] == 0x02` 时，`0xC0..0xCF` 系统命令只转发给基站，不在桶体本地执行。
- `frame[2] != 0x02` 时，桶体端按本地命令逻辑处理 A 段/C 段命令；普通 B 段命令不转发。

## 7. 基站数据合并上报

基站端通过 USART2 发来的帧，只有在帧自身 `frame[2] == 0x02` 时才会被接受并合并上报。

处理逻辑：

1. 基站帧通过帧头和校验。
2. 检查 `frame[2] == 0x02`。
3. 保存 `frame[16]..frame[28]` 到桶体本地 `base_data[13]`。
4. 同时刷新基站连接时间 `base_last_rx_tick` 和桶体周期上报时间 `last_status_tx_tick`。
5. 立即构建一帧桶体状态，将基站数据放入 `frame[16]..frame[28]` 后发送给 Linux 主控端。

基站原始帧不会单独转发给 Linux。如果基站帧的 `frame[2]` 不是 `0x02`，代码直接忽略，不更新连接时间，也不触发上报。

## 8. 基站连接状态

基站在线状态通过 `UART_Comm_IsBaseConnected()` 判断：

```text
base_last_rx_tick != 0
且 HAL_GetTick() - base_last_rx_tick < 3000 ms
且 AD_DCIN > 13.0 V
且基站返回 frame[4] == 1
且 base_safe_stop_pending == 0
```

上报给 Linux 的字段：

```text
frame[4] = UART_Comm_IsBaseConnected()
```

含义：

| `frame[4]` | 含义 |
|---:|---|
| `0` | DCIN 未接入、基站接收超时、基站未确认收到桶体帧，或重连安全停机尚未确认 |
| `1` | 电源接入和双向串口通信均正常 |

注意：只有被 `UART_Comm_ProcessBaseFrame()` 接受的基站帧才会刷新连接时间，也就是帧必须合法且 `frame[2] == 0x02`。

基站在线建立不要求 Linux 使用透传模式，但必须先收到至少一帧合法 Linux 数据，且 Linux
持续在线。此后若 1000 ms 没有业务帧发往基站，桶体主动发送一帧
`frame[2]=0x02、frame[3]=0x00` 的实时水位/温度心跳。Linux 发送的透传帧会自然
刷新发送时间；兜底心跳只在基站发送槽完全空闲时发送，并在 B2 令牌握手期间暂停。

掉线安全规则：

- 排水授权要求 Linux 在线且基站全部在线条件（包括重连安全停机确认）成立；授权撤销时，泵阀底层立即退出排水，所有排水入口（包括调试 B4）都会被拒绝。
- 基站由在线转离线时，桶体停止当前输出和充电，并尝试发送内部安全帧 `B1 + frame[28]=0xA5`，让仍可接收数据的基站立即关闭全部输出。
- Linux 超时后桶体发送同一安全帧并停止基站心跳；即使安全帧没有送达，基站自身也会在 5 s 收包超时后关闭全部输出。
- 重新连接时桶体会重复发送安全 B1，收到基站回显 `frame[3]=B1、frame[23]=0x03` 后才上报在线；断线前的排水、充电或其它动作不会恢复，必须由新的有效命令重新启动。

## 9. 桶体端主动上报给主控端

桶体端每 1000 ms 主动向 Linux 主控端发送一帧状态；处理主控有效命令后也会立即回一帧状态。

状态帧字段：

| 字节 | 内容 |
|---:|---|
| `frame[0]` | `0x55` |
| `frame[1]` | `0xAA` |
| `frame[2]` | 最近一次 Linux 合法帧的链路模式 `last_link_mode` |
| `frame[3]` | 最近一次命令 `SystemMonitor_GetCommand()` |
| `frame[4]` | 基站连接状态 |
| `frame[5]` | 水位协议值 |
| `frame[6]` | 温度整数值；温度传感器异常时为 0 |
| `frame[7]` | 电机档位 |
| `frame[8]` | UV 状态 |
| `frame[9]` | 剩余定时分钟数 |
| `frame[10]` | 固定为 `0x00` |
| `frame[11]` | 电池百分比：18.5 V及以下为 `0x00`，25.0 V及以上为 `0xFF`；中间值按线性百分比使用BCD，例如42%=`0x42` |
| `frame[12]` | 主状态 |
| `frame[13]` | 子状态 |
| `frame[14]` | 错误码 1 |
| `frame[15]` | 错误码 2 |
| `frame[16]..frame[28]` | 基站在线时为最新基站数据 `base_data[13]`；基站离线时全部为 `0` |
| `frame[29]` | 校验和 |

每次收到合法基站中转帧都会立即发送一帧合并状态，并从该时刻重新计算桶体的 1000 ms 周期，避免同一周期内重复上报。基站停止发送后，桶体会在最后一帧基站数据约 1 秒后恢复周期上报；超过 3 秒后，状态帧的连接状态为 `0`，基站数据区清零。Linux 命令响应仍会额外触发即时状态上报。

`frame[9]` 定时分钟数来自 `SystemMonitor_GetTimerRemainingMin()`。当前逻辑为剩余完整分钟，例如：

```text
10:00 -> 10
09:59 -> 9
08:59 -> 8
```

定时真正结束判断使用秒级剩余时间，避免最后 59 秒因为分钟数为 0 而提前关机。

## 10. 运行时数据流总结

主控控制桶体：

```text
Linux 主控 -> USART1 -> 桶体解析 -> 执行 A 段/C 段命令 -> USART1 回状态帧
```

主控透传到基站：

```text
Linux 主控 -> USART1 -> frame[2]=0x02 -> 普通命令原帧发给基站；0x00 空闲命令填入桶体实时水位/温度后发给基站；A 段和 0xB4 同时本地解析
```

基站回主控：

```text
基站 -> USART2 -> frame[2]=0x02 的合法帧 -> 更新 base_data 和连接/周期时间 -> 构建桶体合并状态帧 -> USART1 发给 Linux
```

桶体主动上报：

```text
每 1000 ms -> 构建桶体状态帧 -> 在线时携带基站数据，离线时基站数据区清零 -> USART1 发给 Linux
```

日志输出：

```text
每 1000 ms -> USART3 输出文本日志，不参与协议交互
```
